**Step 1: Create src/app/api/cutoff/route.ts**

Create the directory src/app/api/cutoff/ and write route.ts:

```typescript
import type { NextRequest } from "next/server";
import { NextResponse } from "next/server";

import { eq } from "drizzle-orm";

import { db, schema } from "@/lib/db";

export const dynamic = "force-dynamic";

export async function GET(request: NextRequest) {
  const authHeader = request.headers.get("authorization");
  const cronSecret = process.env.CRON_SECRET;

  if (!cronSecret || authHeader !== `Bearer ${cronSecret}`) {
    return new Response("Unauthorized", { status: 401 });
  }

  await db
    .update(schema.ordering_config)
    .set({ is_ordering_open: false, updated_at: new Date() })
    .where(eq(schema.ordering_config.id, 1));

  return NextResponse.json({ ok: true });
}
```

CRITICAL constraints (per CONTEXT.md D-06 and RESEARCH.md anti-patterns):
- MUST NOT import or call `auth()` from `@/auth` — Vercel invokes cron routes with no session cookie
- Auth is ONLY the `Authorization: Bearer ${CRON_SECRET}` header check
- `dynamic = "force-dynamic"` prevents caching of this route
- Use `new Response("Unauthorized", { status: 401 })` for the 401 (plain text, not JSON)
- Use `NextResponse.json({ ok: true })` for the 200 (matches codebase convention)
- Import `{ eq }` from `"drizzle-orm"` for the WHERE clause
- Import `{ db, schema }` from `"@/lib/db"`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Cron → /api/cutoff | External invocation with no session cookie; CRON_SECRET is the sole auth |
| Internet → /api/cutoff | Any external actor could attempt to call this URL directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | GET /api/cutoff | mitigate | `Authorization: Bearer ${CRON_SECRET}` header check — return 401 immediately if missing or wrong. CRON_SECRET must be set in Vercel env vars (see LAUNCH-CHECKLIST.md). |
| T-06-02 | Denial of Service | GET /api/cutoff | accept | Route only sets a boolean; no expensive computation. Idempotent — repeated calls are safe. Rate limiting not needed at MVP volume. |
| T-06-03 | Tampering | ordering_config.is_ordering_open | accept | Route only sets to false (never re-opens). Admin re-opens manually via settings page. No tampering vector that worsens the state. |
| T-06-04 | Information Disclosure | CRON_SECRET in logs | mitigate | Route logs nothing about the secret. 401 response body is plain "Unauthorized" (no hint about correct format). |
</threat_model>
