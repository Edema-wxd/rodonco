## ORM / Query Strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Drizzle ORM | Schema-as-TypeScript, edge-compatible, great Neon integration, type-safe queries. Popular for Next.js 15 + Vercel. | ✓ |
| Prisma | Well-known ORM, Prisma Studio, but slower cold starts on Vercel serverless with Neon. | |
| Raw SQL via @neondatabase/serverless | Zero abstraction, best cold-start performance, but no type safety. | |

**User's choice:** Drizzle ORM

---

## Schema Management (Drizzle)

| Option | Description | Selected |
|--------|-------------|----------|
| Drizzle schema + push | Schema-as-code in drizzle/schema.ts, `drizzle-kit push` to apply. No migration files for MVP. | ✓ |
| Drizzle migration files | drizzle-kit generate produces versioned SQL migration files. More rigorous but heavier for MVP. | |

**User's choice:** Drizzle schema + push

---

## Admin Authentication

| Option | Description | Selected |
|--------|-------------|----------|
| NextAuth.js v5 (Credentials) | Standard for Next.js. Credentials provider, JWT sessions, middleware route protection. Admin creds in Neon DB. | ✓ |
| Neon Auth (Stack Auth) | Neon's managed auth service. More powerful than needed for 1-2 admins, extra vendor dependency. | |
| Lightweight JWT (custom) | Custom bcrypt check + jose JWT in httpOnly cookie. Full control but reinvents what NextAuth solves. | |

**User's choice:** NextAuth.js v5 (Credentials)

---

## Admin Credentials Storage

| Option | Description | Selected |
|--------|-------------|----------|
| Neon DB admins table | `admins` table (email, password_hash) in Drizzle schema. Consistent with data layer. | ✓ |
| Env var (single admin) | ADMIN_EMAIL + ADMIN_PASSWORD_HASH in env vars. Simplest for MVP — no DB table. | |

**User's choice:** Neon DB admins table

---

## Uploadthing Setup Depth

| Option | Description | Selected |
|--------|-------------|----------|
| Full setup now | Install uploadthing, create route handler + file router (productImage, 4MB), env vars. Phase 4 just uses UploadButton. | ✓ |
| Install + env vars only | Install package, document env vars, defer route handler to Phase 4. | |

**User's choice:** Full setup now

---

## RLS on Neon

| Option | Description | Selected |
|--------|-------------|----------|
| Drop RLS entirely | All access goes through server-side Route Handlers. API layer is the security boundary. No Postgres roles needed. | ✓ |
| Keep RLS with Neon roles | Create `web_anon` role, adapt existing policies. More complex setup and maintenance. | |

**User's choice:** Drop RLS entirely
