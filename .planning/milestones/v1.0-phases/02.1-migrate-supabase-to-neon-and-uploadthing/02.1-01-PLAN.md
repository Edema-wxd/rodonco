Drizzle column type mappings (verified in RESEARCH.md Pattern 3):
- UUID PK default gen_random_uuid() -> `uuid("id").defaultRandom().primaryKey()`
- TEXT NOT NULL -> `text("name").notNull()`
- BOOLEAN NOT NULL DEFAULT true -> `boolean("is_active").notNull().default(true)`
- INTEGER NOT NULL -> `integer("price_ngn").notNull()`
- TIMESTAMPTZ NOT NULL DEFAULT now() -> `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
- DATE NOT NULL -> `date("week_of").notNull()`
- TEXT UNIQUE NOT NULL -> `text("reference").unique().notNull()`
- UUID FK CASCADE -> `uuid("product_id").notNull().references(() => products.id, { onDelete: "cascade" })`
- INTEGER PK default 1 (single-row config) -> `integer("id").primaryKey().default(1)`

Drizzle db instance pattern (verified — RESEARCH.md Pattern 1):
```typescript
import "server-only";

import { neon } from "@neondatabase/serverless";
```

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Neon Postgres ⇄ Server (Vercel/local) | Connection string is sensitive; must never reach client bundle |
| Server file ⇄ Client component import | `lib/db/index.ts` must not be importable by client code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-01 | Information Disclosure | `DATABASE_URL` env var | mitigate | Env var declared without `NEXT_PUBLIC_` prefix; Task 1 adds `import "server-only"` to `src/lib/db/index.ts` so any client-side import fails the Next.js build (per D-14, RESEARCH.md Pitfall 3) |
| T-02.1-02 | Tampering | DDL push via PgBouncer | mitigate | `drizzle.config.ts` uses `DIRECT_DATABASE_URL` (non-pooled) — pooled URL hangs/errors on DDL, would tempt developer to disable safety checks (RESEARCH.md Pitfall 1) |
| T-02.1-03 | Information Disclosure | Drizzle schema accidentally exposing PII columns to client | mitigate | All schema imports go through `lib/db/index.ts`, which is `import "server-only"`-guarded; schema file is never directly imported by client code |
| T-02.1-04 | Spoofing / privilege escalation | RLS removed (D-13) | accept | Per D-13: Route Handler layer is the security boundary; pre-launch app has no anon DB access. Acceptable for MVP because customers never get DB credentials. Future ASVS-L2 work would require service-role separation, deferred. |
| T-02.1-05 | SQL Injection | All queries via Drizzle | mitigate | Drizzle parameterized queries — never use raw `sql\`\`` with user input; this plan establishes the convention |

</threat_model>
