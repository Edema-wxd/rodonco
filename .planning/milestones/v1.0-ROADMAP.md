## Overview

A complete food-prep ordering platform built for the Nigerian market. Customers browse fresh ingredients and cooking kits, configure preparation styles, add to cart, and pay via Paystack inline popup — all without creating an account. The platform enforces a weekly ordering window (Sunday–Thursday) automated by Vercel Cron and delivers every Saturday. The admin panel covers full product CRUD, order management, analytics, and 7 operational tools (prep list, manifest, bulk status transitions, customer search, analytics week picker, delivery config, pending order cleanup).

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Neon Postgres + Drizzle over Supabase PostgreSQL | Full ORM control, schema-as-code, no RLS complexity | ✓ Validated Phase 4 |
| NextAuth v5 Credentials over Supabase Auth | Neon migration removed Supabase; lighter server-only JWT sessions | ✓ Validated Phase 4 |
| UploadThing over Supabase Storage | Typed auth-gated endpoint, simpler than Supabase Storage | ✓ Validated Phase 4 |
| `motion` (not `framer-motion`) | Package was rebranded; imports must be `"motion/react"` | ✓ |
| Zod pinned to v3 | v4 breaks `@hookform/resolvers` v3 as of April 2026 | ✓ |
| Webhook reads `req.text()` before JSON parsing | Body stream is one-time-read; JSON parsing first silently breaks HMAC | ✓ |
| Prices stored as integer kobo | Avoids floating point precision bugs in financial calculations | ✓ |
| No customer accounts | Reduces friction; customers checkout as guests | ✓ |
| Vercel Cron for cutoff (not Supabase Edge Function) | Simpler ops; Vercel manages the scheduler | ✓ |
| Tag-based revalidateTag over ISR TTLs | Instant shop-page refresh after admin mutations, no bounded stale window | ✓ Phase 9 |
