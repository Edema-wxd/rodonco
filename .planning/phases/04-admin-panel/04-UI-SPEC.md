## Layout Contract

### Shell Structure

The existing `src/app/admin/layout.tsx` must be refactored. Replace the current header + max-7xl container with:

```
<div class="flex min-h-screen bg-gray-50">
  <aside class="w-56 shrink-0 border-r bg-white flex flex-col">   <!-- sidebar -->
  <main class="flex-1 overflow-y-auto">                            <!-- content area -->
```

Sidebar is fixed/sticky — it does not scroll with content. Width: 224px (14rem / `w-56`).

Primary focal point per page type:
- Orders: the orders table
- Products: the product list/table
- Analytics: the stat cards grid
- Settings: the OPEN/CLOSED state label
- Login: the Sign In button

### Login Page (`/admin`)

Layout: full viewport, `bg-gray-50`, vertically + horizontally centered.

Card: `bg-white border rounded-xl shadow-sm p-8 w-full max-w-sm`

Contents (top to bottom):
1. Heading: "Sign in" — 20px semibold
2. Email input (label: "Email address")
3. Password input (label: "Password", type=password)
4. Sign In button — full width, variant=default
5. Error state: inline text below button — 14px, `text-destructive`

No logo. No brand imagery. No "forgot password" link.

### Content Area

Each page content lives in: `<div class="p-6">` (24px padding all sides).

Page heading row: `<h1 class="text-xl font-semibold text-gray-900">` + optional action button (right-aligned, flex justify-between).

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline padding |
| sm | 8px | Compact row padding, badge padding |
| md | 16px | Default form field spacing, card padding |
| lg | 24px | Page content padding (`p-6`) |
| xl | 32px | Section gaps within a page |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top/bottom breathing room (unused at MVP) |

Exceptions:
- Sidebar nav link height: 40px — achieved via `py-3` (12px top+bottom) + `min-h-10` on the nav link element
- Sidebar width: 224px (`w-56`)
- Table row height: natural content height — no fixed row height constraint

## Color

The admin panel uses the existing shadcn neutral token system — no brand warm palette.

| Role | CSS Token | Approx. Hex | Usage |
|------|-----------|-------------|-------|
| Dominant (60%) | `--background` / `bg-gray-50` | #f9fafb | Page background, outer shell |
| Secondary (30%) | `--card` / `bg-white` | #ffffff | Sidebar, table, cards, login card, drawer |
| Accent (10%) | `--primary` (near-black) | #1a1a1a | Active nav, primary button fill, stat card heading |

- Primary action buttons (Sign In, Save Settings, Add Product)
- Active sidebar nav link background + text

## Component Interaction Contracts

### Orders Table

**Source:** CONTEXT.md D-08, D-09, D-10, D-11, D-12

- Renders as shadcn `<Table>` with columns: Reference, Customer, Phone, Date, Status, Total (NGN), (expand chevron)
- Default sort: `created_at DESC`
- Row expansion: clicking anywhere on the row toggles an inline expanded section (collapsible `<tr>` with `colspan={7}`). Expanded section shows:
  - Per-item rows: product name + quantity + prep option label
  - Allergy notes (if any): italic 14px text-gray-500
  - Delivery address: 14px text-gray-600
  - Expand/collapse controlled via local state (`useState` map keyed on order ID)
- Chevron icon: `ChevronDown` 16px, rotates 180deg when expanded (CSS `transition-transform duration-150`)
- Status column: shadcn `<Select>` inline — width `w-36`. On change triggers `PATCH /api/admin/orders/[id]` immediately. No save button.
- Filters (above table): status `<Select>` + delivery week `<Input type="date">` — both in a `flex gap-3` row, right-aligned `<Button>` "Export CSV"
- Empty state (no orders match filter): centered in table body — "No orders found" 14px text-gray-500, "Try adjusting your filters." 14px text-gray-400
- Pagination: simple prev/next — 50 rows per page. Display: "Showing 1–50 of N orders" 14px text-gray-500

### Product Drawer (Right Side)

**Source:** CONTEXT.md D-13, D-14, D-15, D-16, D-17

- shadcn `<Sheet side="right">` — width: 480px (`max-w-[480px] w-full`)
- Table remains visible/dimmed behind the sheet overlay
- Drawer header: product name (edit) or "New Product" (create) — 20px semibold
- Form layout (top to bottom):
  1. Image upload block — `<UploadButton routeConfig="productImage" />`, shows current image preview (80px × 80px, rounded-md, object-cover) or placeholder
  2. Name input (label: "Product name")
  3. Description textarea (label: "Description", rows=3)
  4. Type select (label: "Type"): Fresh Produce / Cooking Kit
  5. `is_active` Switch (label: "Active on shop") — inline label left, switch right
  6. Variants section: "Size Variants" heading + inline list. Each row: name input + price input (in kobo) + `×` remove button. "+ Add variant" text button appends row.
  7. Prep Options section: "Prep Options" heading + inline list. Each row: label input + `×` remove. "+ Add prep option" text button appends row.
  8. Danger zone: "Delete Product" button — `variant="destructive"` — triggers inline confirmation text "Are you sure? This cannot be undone." + "Confirm Delete" + "Cancel" text buttons. No modal.
- Footer: Save button (`variant="default"`, label: "Save Product") + Cancel button (`variant="ghost"`)
- Atomic save: single POST/PATCH call for product + variants + prep options together
- Variants and prep options managed with `useFieldArray` (RHF)

### Analytics Page (Four Stat Cards)

**Source:** CONTEXT.md D-18, D-19

- Layout: `grid grid-cols-2 gap-6` (2×2 on desktop, 1×1 on mobile via `sm:grid-cols-2`)
- Each card: shadcn `<Card>` with `p-4`
  - Label: 14px text-gray-500 uppercase tracking-wide
  - Metric: 28px font-semibold text-gray-900
  - Sub-label (if applicable): 14px text-gray-400 (e.g. "this week")
- Four cards:
  1. "Total Orders" — integer count
  2. "Total Revenue" — formatted as `₦N,NNN,NNN` (Nigerian locale, no decimals)
  3. "Top Products" — ordered list of 5 items (product name + count), 14px body text, `gap-2`
  4. "Order Status" — three rows: paid / processing / delivered + count each

Top Products card spans full width on desktop: `col-span-2` or laid out as 4th card independently.

Preferred layout: row 1 = Orders + Revenue; row 2 = Top Products (col-span-2 or separate card); row 3 = Status Breakdown.

No charts. No charting library. Plain numbers only.

### Settings Page (Ordering Window Toggle)

**Source:** CONTEXT.md D-03, D-20

- Single card: `<Card>` with `p-6`, max-w-lg, centered
- Card heading: "Ordering Window" — 20px semibold
- Current state label (large, prominent):
  - OPEN: `text-green-700 font-semibold text-[28px]` with `✓ Ordering is OPEN`
  - CLOSED: `text-red-700 font-semibold text-[28px]` with `✗ Ordering is CLOSED`
- Toggle: shadcn `<Switch>` — large (`scale-125` or size="lg"), labeled "Enable ordering"
- Confirmation before CLOSING: inline text appears below toggle: "This will prevent new orders. Confirm?" with "Yes, Close" button (`variant="destructive"`, sm) + "Cancel" (`variant="ghost"`, sm). No modal — inline only.
- No confirmation needed when re-opening (low risk direction).
- Save state: "Save Settings" button triggers `PATCH /api/admin/config`. On success: toast or inline "Saved" 14px text-green-600 that fades after 2 seconds.

## Animation Contract

Framer Motion is available (`motion/react` import, not `framer-motion`).

| Element | Animation | Duration |
|---------|-----------|----------|
| Sidebar nav active indicator | none — instant bg swap | — |
| Order row expand/collapse | `motion.div` height animation, `ease-out` | 150ms |
| Row expand chevron rotation | CSS `transition-transform` | 150ms |
| Product drawer open/close | shadcn Sheet handles animation natively | ~200ms |
| Settings "Saved" confirmation text | CSS opacity fade-out via `transition-opacity` | 2000ms |
| Stat card hover | none — utility tool, no decorative hover | — |

No page transition animations. Admin is utility-first — animation is functional only (communicates state change).

## Accessibility Contract

- All form inputs have explicit `<label htmlFor>` bindings
- Status select in orders table: `aria-label="Update order status"`
- Ordering toggle: `aria-label="Toggle ordering window"` with `aria-checked` state
- Expandable rows: `aria-expanded` attribute on the trigger cell
- Sidebar nav links: `aria-current="page"` on the active link
- Delete confirm buttons: `aria-describedby` pointing to the confirmation text
- Minimum touch target: 40px height for all interactive nav and table controls
