# Phase 02.1: migrate-supabase-to-neon-and-uploadthing — Plan 01 Summary

**Neon-backed Postgres foundation with Drizzle schema + server-only db client, plus a repeatable smoke test that verifies all 7 tables and seeds `ordering_config`.**

## Accomplishments
- Declared all 7 tables (6 legacy + `admins`) in `drizzle/schema.ts` matching the Supabase SQL column names.
- Added `src/lib/db/index.ts` Drizzle client guarded by `import "server-only"` for Next.js safety.
- Confirmed schema is pushed idempotently via `npx drizzle-kit push` and verified with `scripts/smoke-test-db.ts`.

## Task Commits
1. **Task 1: Install Drizzle + Neon packages, declare all 7 Drizzle tables, create db client** - `33ba8f8`

## Files Created/Modified
- `drizzle/schema.ts` - Drizzle table definitions for `products`, `product_variants`, `product_prep_options`, `orders`, `order_items`, `ordering_config`, `admins`
- `src/lib/db/index.ts` - server-only Drizzle db instance
- `drizzle.config.ts` - Drizzle Kit config using `DIRECT_DATABASE_URL`
- `scripts/smoke-test-db.ts` - connectivity + schema presence + `ordering_config` seed (idempotent)

## Deviations from Plan
- **DATABASE_URL pooling**: Neon pooler hostname failed DNS resolution here, so `DATABASE_URL` was temporarily set to the working direct host to unblock local dev + smoke tests. `DIRECT_DATABASE_URL` remains the source of truth for DDL pushes.

## Issues Encountered
- Neon pooled hostname (`-pooler`) was not resolvable (DNS `ENOTFOUND`) in this environment.
