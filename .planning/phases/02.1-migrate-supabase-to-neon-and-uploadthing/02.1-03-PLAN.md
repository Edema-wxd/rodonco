FileRouter pattern (RESEARCH.md Pattern 7):
```typescript
// app/api/uploadthing/core.ts
import { createUploadthing, type FileRouter } from "uploadthing/next";
import { UploadThingError } from "uploadthing/server";
import { auth } from "@/auth";

const f = createUploadthing();

export const ourFileRouter = {
  productImage: f({
    image: {
      maxFileSize: "4MB",
      maxFileCount: 1,
    },
  })
    .middleware(async ({ req }) => {
      const session = await auth(); // MUST await — auth() is async (Pitfall 5)
      if (!session?.user) throw new UploadThingError("Unauthorized");
      return { adminId: session.user.id };
    })
    .onUploadComplete(async ({ metadata, file }) => {
      return { url: file.url };
    }),
} satisfies FileRouter;

export type OurFileRouter = typeof ourFileRouter;
```

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ⇄ /api/uploadthing | Unauthenticated requests must be rejected before any file is accepted |
| Uploadthing CDN ⇄ products.image_url | URL stored is from a controlled CDN — no XSS risk via image URL itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-12 | Elevation of privilege | Anonymous file upload | mitigate | `core.ts` `.middleware()` calls `await auth()` (Pitfall 5 — `await` mandatory); throws `UploadThingError("Unauthorized")` if no session — verified by curl test in Task 2 |
| T-02.1-13 | Denial of Service | Oversized upload | mitigate | `productImage` route declares `maxFileSize: "4MB"` and `maxFileCount: 1`; Uploadthing enforces server-side before file write |
| T-02.1-14 | Tampering | Wrong env var (v6 names) | mitigate | Task 1 acceptance criteria explicitly check `UPLOADTHING_SECRET` and `UPLOADTHING_APP_ID` are absent (Pitfall 6); `UPLOADTHING_TOKEN` must be the single source |
| T-02.1-15 | Information Disclosure | UPLOADTHING_TOKEN exposed in client bundle | mitigate | No `NEXT_PUBLIC_` prefix; `core.ts` is a server route handler (always server-side); SSR plugin only ships routerConfig (public schema), not the token |
| T-02.1-16 | Spoofing | Wrong file type accepted as productImage | accept | Uploadthing enforces `image` MIME at route level; SVG XSS risk acknowledged but acceptable for admin-only upload (admin is trusted role) — could harden in v2 by restricting to `image/jpeg`, `image/png`, `image/webp` only |

</threat_model>
