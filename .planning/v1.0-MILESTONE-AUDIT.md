### Integration Issues (All WARNING — No Blockers)

#### ⚠️ W-01: Ordering Config 15s Cache Staleness

**Affects:** CHKT-03, SHOP-09, INFRA-02  
**Location:** `src/app/api/admin/config/route.ts` (PATCH), `src/app/api/cutoff/route.ts` (GET)  
**Issue:** Both routes update `ordering_config.is_ordering_open` in DB but do NOT call `revalidateTag`/`revalidatePath`. The customer-facing `getOrderingConfig()` uses `unstable_cache` with `revalidate: 15` seconds. Comment in `orders/init/route.ts` line 6 claims "no cache" — this is **incorrect**.  
**Impact:** After admin closes ordering (or cron fires), customers can still reach checkout for up to 15 seconds. Low business impact (bounded race window).  
**Fix:** Add `revalidateTag("shop-ordering-config-v1")` to both routes after DB update.

#### ⚠️ W-02: CONF-02 Error Variant Hardcoded

**Affects:** CONF-02  
**Location:** `src/app/(customer)/order/[ref]/page.tsx` line 38  
**Issue:** `errorVariant` is always `"not-found"` even for orders that exist but are `pending`. The `"not-paid"` variant exists in `OrderConfirmationView` but is never used. Customers in the webhook-delay window see "Order not found" instead of "Payment not confirmed."  
**Impact:** UX degradation in webhook-lag window (typically <5 seconds).

#### ⚠️ W-03: ReminderForm Missing Client Saturday Validation

**Affects:** NOTF-01  
**Location:** `src/components/admin/settings/ReminderForm.tsx`  
**Issue:** API correctly rejects non-Saturdays (400) but client shows generic "Failed to send reminders. Check server logs." with no hint to select a Saturday.  
**Impact:** Admin UX confusion on non-Saturday selection.

#### ⚠️ W-04: manifest.ts + pendingOrders.ts Full Table Scan

**Affects:** OPS-03, OPS-04  
**Location:** `src/lib/admin/manifest.ts`, `src/lib/admin/pendingOrders.ts`  
**Issue:** Both fetch all `order_items` rows then filter in memory. Functional at MVP volume.  
**Impact:** Performance degradation at scale. No functional blocker today.
